# ADR-0005: 画像付きシェアのUI設計

## ステータス

採用

## コンテキスト

Issue #14 でジャケット画像付きシェア機能を実装するにあたり、X Web Intent には画像添付パラメータが存在しないという技術的制約がある。画像付きシェアは Web Share API (`navigator.share({ files })`) 経由でのみ実現可能。

当初は「画像を添付」トグルを SettingsPanel に追加し、ON/OFF で切り替える設計とした。しかし実機テスト（iOS + Chrome、Windows11 + Chrome）で以下の問題が発覚した:

1. トグル ON でも「𝕏 で投稿」ボタンでは画像が付かない → ユーザーが混乱
2. PC Chrome でも `navigator.canShare({ files })` が `true` を返すため、トグルが disabled にならない
3. PC の共有シートには X アプリが表示されないため、画像付きシェアの実用性がない

業界調査の結果:
- SNS 個別ボタンと Web Share API ボタンの同時表示は非推奨（CSS-Tricks 調査: 60% がカスタム共有ボタン未使用）
- 「テキスト/画像」切替トグルは定番パターンとして存在しない
- YouTube・Pinterest 等は OGP に依存し、画像添付の問題自体を回避

## 検討した選択肢

| 選択肢 | 概要 | 評価 |
|--------|------|------|
| A: UA 判定でモバイル/PC を分ける | モバイル → Web Share API、PC → Intent | UA 判定の信頼性低下（iPad はデスクトップ UA 返す等）、メンテコスト増 |
| B: canShare() だけで割り切る | API 使えるなら Web Share API ボタン表示 | PC Chrome で「押してみたけど X がなかった」が発生 |
| **C: 全ボタン常時表示** | 排他的出し分けをやめ、画面幅で優先度変更 | 採用 |

## 決定

**選択肢 C: 全ボタン常時表示、画面幅で視覚的優先度を変更**

- 「画像を添付」トグルを廃止
- ボタン構成を固定: 🖼 画像付きで共有（canShare 時のみ）→ 𝕏 で投稿 → 🦋 Bluesky → 📋 投稿文をコピー
- スマホ（画面幅狭）: 「画像付きで共有」がプライマリ CTA
- PC（sm: 以上）: 「𝕏 で投稿」「Bluesky」がプライマリ CTA
- UA 判定は不使用。`@media` による画面幅ベースの制御のみ

## 理由

- トグルが消えるので「ON にしたのに画像が付かない」問題がそもそも発生しない
- UA 判定不要で、iPad・Chromebook・Windows タブレット等の境界ケースで壊れない
- PC Chrome で共有シートに X がなくても、「𝕏 で投稿」ボタンが常に見えているのでフォールバック可能
- 将来 Windows/macOS の共有シートが改善されたら、コード変更なしで恩恵を受けられる
